01 · 起点

为什么要学AI：浅层使用 vs 深入使用

同样是用AI，效率和收获可能相差巨大。关键在于你用到了什么程度。

浅层使用

只是更聪明的搜索引擎

  • "帮我写一封请假邮件" → 复制粘贴完事
  • "Python怎么读取CSV？" → 试一下，能跑就行
  • "帮我翻译这段英文" → 翻译完，结束

深入使用

真正的AI副手

  • 模糊想法 → 理清思路 → 可执行计划
  • 让AI读文件、改代码、跑命令、调试
  • 把重复流程沉淀成Skill → 一句话调用

真正的区别在于是否学会了

  1. 把目标、背景、约束说清楚
  2. 让AI接触到你的真实文件和上下文
  3. 把重复的流程变成可复用的方法
  4. 知道哪些地方可以信任AI，哪些地方必须自己判断

工具 出品方 特点 适合人群

03 · 核心功能

Claude Code 三个标签页怎么用

理解这三个标签页的定位，是用好 Claude Code 的关键。

Chat
普通对话
就像和聪明的朋友聊天，问问题、让它写文案、翻译、分析、头脑风暴。

不会接触你电脑上的任何文件。
纯问答 写作 翻译 聊天
Code
接入本地项目（最强大）
让AI打开你电脑上的文件夹，它可以读取你的文件、提修改建议、写代码、运行命令。

这是 Claude Code 最强大的地方。
写代码 改文件 调试 写脚本 做小工具
Cowork
云端后台任务
像是派出一个后台助手，让它独立完成需要较长时间的任务。

你不需要一直盯着。
跑长分析任务 大范围代码修改 不需要实时交互的工作
04 · 进阶

从"逐次批准"到"适度放权"

权限管理是安全使用AI的核心，循序渐进是关键原则。

逐次批准（默认，推荐新手）

AI每次想修改文件或运行命令，都会先问你。
好处是你完全掌控，不会出意外。

自动接受编辑（熟悉后切换）

AI修改文件时不再逐一询问，改完后你可以看diff（改动对比），不满意可以撤回。

适合你已经比较信任AI判断的时候。

实用建议

有了感觉之后可以切换到"自动接受编辑"。如果是涉及重要文件或生产环境的操作，随时可以切回"逐次批准"。永远不要在第一次使用就给AI最大权限。

05 · 进阶工具

这几个Skill新手最值得先了解

Skill是Claude Code的核心能力扩展，先掌握这三个，能少走很多弯路。

Enhance
解决什么问题
脑子里有个想法但说不清楚，AI收到模糊指令给的结果也很模糊。 Enhance在AI执行之前，先帮你把需求本身说清楚——补充缺失的上下文、明确目标、理清约束。
/enhance 你的想法
Superpowers
解决什么问题
防止"上来就干"的模式——想到什么写什么，改到哪算哪，结果反复返工。 Superpowers强迫你按流程走：头脑风暴 → 写计划 → 分步执行 → 验证复查。
包含：Brainstorming · Writing Plans · Executing Plans · Test-Driven Development · Debugging · Code Review
gstack
解决什么问题
把Claude Code变成一个虚拟工程团队——有产品经理梳理需求、有工程师架构评审、有QA测试、有安全专家检查、有发布工程师推代码。
/office-hours 产品复审 /review 代码审查 /qa 浏览器测试 /ship 推送代码
先不管 Hermes Agent。等你对基本使用已经很熟练、开始需要"多个AI agent自动协作"这类进阶能力时，再去了解它。
06 · 沟通方法

如何精准全面地表达需求

好的prompt是高效使用AI的基础。以下五个要素，帮你把需求说清楚。

要素 说明 例子
背景 你在做什么，为什么要做 "我在准备下周的项目汇报"
目标 你想要什么结果 "需要一份10页以内的PPT大纲"
约束 有什么限制条件 "受众是不懂技术的管理层"
输出形式 希望结果长什么样 "用Markdown格式，每页标题+3个要点"
参考样例 有没有你喜欢的例子 "风格参考苹果发布会的简洁感"

高手秘诀

没有人能一句话就把需求说得毫无歧义。高手也不能。真正高效的用法是：先说个大概 → 让AI反问 → 来回讨论几轮 → 让AI帮你重写需求（Enhance） → 然后再进入执行。

07 · 行动计划

7天入门计划

跟着这个计划走，一周入门AI。不用赶，每天一个任务，轻松上手。

Day 1
装好工具，完成第一次对话
下载安装Claude Code桌面端，创建账号，在Chat里随便聊几句，消除恐惧感。
Day 2
让AI帮你写一样东西
想一个最近真正需要写的东西，让AI帮你写。学会用"背景+目标+约束+输出形式"来表达需求。
Day 3
试用Code模式，让AI读你的文件
在电脑上找一个不重要的文件夹，用Code标签页让AI打开它，体验AI直接操作本地文件的能力。
Day 4
让AI帮你整理信息
找一段真实的会议记录、课堂笔记或读书笔记，让AI帮你整理成结构化格式。
Day 5
试用Enhance，学会让AI帮你说清楚需求
想一个一直想做但没想清楚的事情，用/enhance让AI帮你把模糊想法变成清晰需求。
Day 6
让AI帮你做一个小工具
想一个简单但有用的小工具需求，在Code标签页里让AI帮你写。你完全不需要会编程。
Day 7
回顾 + 创建你的第一个Skill
回顾这一周你用AI做的事，找出重复做过的事，把它做成你的第一个Skill。
08 · 生存指南

小白须知（第一天就要知道的基本常识）

这六条经验，是很多人花了很长时间才明白的道理。现在告诉你，可以少走很多弯路。

不要随便粘贴敏感信息

AI对话内容可能用于模型训练或存储在云端。不要粘贴密码、API密钥、银行信息、身份证号。

重要结果要自己核验

AI会非常自信地给你一个答案，但那个答案可能是错的。尤其是：数字和数据、链接和引用、法律/医疗/财务建议、最新信息。

权限要逐步开放

第一次用Code模式？先让AI读文件，不要直接让它改。反复确认AI行为符合预期后，再考虑开放"自动接受"。

成本和速度是trade-off

最强模型≠最好选择。日常任务用中档模型即可，遇到难题再切回最强模型。

学AI的最好方式是边做边学

不要试图先把所有功能都研究透再开始用。找一个你真正需要做的小事 → 试着用AI来做 → 遇到问题、学到东西 → 下一次做得更好。

把好用的东西沉淀下来

每次发现一个特别好用的Prompt写法或有效提问方式，简单地存到笔记里，进阶的做成Skill，更进阶的持续迭代你的Skill。
