高效工作案例

工具选对了，数据驱动让效率翻倍

案例 1 · 15分钟完成完整部署
从主题策划到腾讯云部署，15分钟全搞定
大羽在 15-20 分钟内完成了从主题策划、流程分解、编码落地页、部署到腾讯云对象存储服务器、再到域名映射的全套工作。这不是炫技——这套流程背后的逻辑是可复用的：用 cursor 工具告知 MD 文件为分享提纲，让它优化并生成落地页，5 分钟内完成部署。
案例 2 · 三天完成整场活动策划
活动从零到上线，三天搞定一切
秦岭AI白客松活动从无到完成策划、宣发、海报、物料、网站等所有工作，仅花三天时间。快速响应的背后是数据驱动的工作方式：以一次线上电话会议录音为起点，不断加工分析数据，后续所有工作都是数据堆叠的结果。
工具使用策略
因正版软件成本问题，使用多个模型协同：不同屏幕分配不同任务——cursor 用于图像性工作，正式慎重的工作使用付费模型。这是务实的技术选型：工具不是越贵越好，而是匹配场景最重要。
核心观点

数据治理：AI 协作的隐形基础设施

核心洞察
工作流协同的主要成本在哪里？不是工具，不是模型，而是数据获取和数据流转。大多数团队引进先进工具后效率依然低下，根因不在于工具不好，而在于数据散落在各处、无法被有效利用。

数据获取成本高的原因

  • 寻找成本：从过往经验、硬盘、网盘找数据极为耗力，尤其是在时间压力下
  • 生产成本：重新创造或采集数据往往比找到现有数据更费时费力
  • 鉴权成本：调取数据不仅需要时间，还需反复鉴权、验证，耗费 token
  • 上下文成本：数据上下文会随时间变化，历史数据的可用性逐渐降低

数据流转的三大环节

  • 获取：从各种来源收集原始数据，占总成本的最大比重
  • 传播：数据在不同平台、不同成员之间流转，需要多次格式转换和传递
  • 处理：对数据进行清洗、结构化、分析和沉淀，这是 AI 能够介入的主要环节
数据聚合的优势
  • 挖掘潜在联系：AI 能挖掘数据之间的潜在联系，聚合数据可让 AI 更好地了解用户——就像大脑神经元产生连接一样
  • 节省时间成本：使用 CLI 接口让大语言模型与数据源直连，可节省数据调取和流转的时间
  • 形成数据资产：数据成为可复用、可积累、可传承的资产，而非一次性消耗品

数据分类

  • 结构化数据：有明确字段定义的数据，每个字段描述与内容相关联。例如问题收集表——有姓名、问题类型、紧急程度等字段
  • 非结构化数据：来自自然语言，如日常交流产生的文本、录音、聊天记录等
  • 离散数据：来自传感器——视频监控（光学传感器）、声学传感器等，可用于采集非结构化数据
实操方法

如何建立数据治理习惯

第一步
选定数据聚合平台
使用有 CLI 接口的大厂平台，将不同类型的数据放入同一体系中。推荐使用飞书等具备良好 API 和 CLI 工具的平台，方便与大语言模型直连。
第二步
建立收集习惯
收集表是获取结构化数据的有效途径。每次活动、会议、项目都建立对应的收集表，形成可追溯的数据资产。例如这次白客松活动，通过问题收集表获取参与者的真实痛点。
第三步
用工具处理离散数据
利用 cursor 等工具将离散型数据转化为结构化数据。例如将飞书录音文档和目标结构性表格交给 cursor，让其整理数据——这比手动整理快数十倍。
第四步
让数据产生循环价值
各环节产生的数据相互关联，形成循环。活动策划以录音为起点 → 数据加工分析 → 产出落地页 → 新数据产生 → 继续迭代。数据不是一次性消耗品，而是持续产生价值的资产。
没有数据，别聊 LLM
很多团队花大量时间研究各种 LLM、Agent、Skill、MCP，却不愿意在数据治理上投入。事实是：如果没有足够的高质量数据作为输入，再先进的 AI 模型也发挥不出价值。先把数据基础设施建好，再谈上层工具选型。
结构化数据的价值
结构化数据让主持人、主讲人的内容与参与者的需求快速匹配。例如：收到100个问题后，用 AI 按主题分类、与切磋场话题对应，5分钟就能生成精准的问题-场次匹配落地页。这就是数据治理带来的真实效率提升。
核心要点

数据是 AI 协作的第一公里

大羽分享的核心结论
  • 数据获取和流转是工作流协作的主要成本，解决这两个问题是提效的关键
  • 将所有数据聚合在同一套有 CLI 接口的体系中，建立数据治理习惯
  • 收集表是获取结构化数据的有效途径，也是形成数据资产的第一步
  • 工具选型要务实：不同场景用不同工具，不追求一步到位
  • 没有高质量数据，再先进的 AI 工具也无法发挥作用
